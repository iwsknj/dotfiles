# Claude Plan Creation

`claude` CLI を非対話モードで実行し、別コンテキストの Claude にコードベースを分析させて、詳細な実装計画を `plan.md` に作成させるスキル。調査フェーズ（`claude-research`）完了後に使用し、実際のコードベースに基づいた具体的な実装計画を生成する。

## 実行コマンド

```bash
claude -p "<request>" --model opus --effort high --tools "Read,Grep,Glob" > <出力先>/plan.md
```

`--tools "Read,Grep,Glob"` のため Claude 自身はファイルを書き込めない。`plan.md` は stdout のリダイレクトで生成する。

**プロンプトは必ずオプションより前に置く**（`--tools` は可変長引数のため、後ろのプロンプトを吸い込んでエラーになる）。

## パラメータ

| パラメータ                 | 説明                                                           |
| -------------------------- | -------------------------------------------------------------- |
| `-p`                       | 非対話実行（結果を stdout に出力して終了）                     |
| `"<request>"`              | 依頼内容（日本語可）。オプションより前に置く                   |
| `--model opus`             | モデル指定                                                     |
| `--effort high`            | 推論の深さ                                                     |
| `--tools "Read,Grep,Glob"` | 読み取り専用ツールのみ許可（安全な分析用・確認プロンプトなし） |
| `> <file>`                 | 最終メッセージの書き出し先（= `plan.md` の生成先）              |

**対象ディレクトリ**: `claude` に `codex` の `--cd` 相当のオプションはないため、**対象プロジェクトのディレクトリで実行する**。

## 計画ドキュメントの要件

生成される `plan.md` には以下が**必ず含まれる**必要があります：

1. **アプローチの詳細な説明** - 実装方法の全体像と設計思想
2. **実際の変更を示すコードスニペット** - 具体的なコード例（既存コードの修正箇所も含む）
3. **変更されるファイルパス** - 影響を受けるファイルの一覧
4. **考慮事項とトレードオフ** - 実装時の注意点、代替案、パフォーマンスへの影響など

## 使用例

### 基本パターン: 新機能の実装計画

```bash
claude -p "システムを拡張して<ビジネス成果>を実行する新しい機能<名前と説明>を構築したいと考えています。これを実装する方法を概説した詳細な実装計画をMarkdownで出力してください。コードスニペットを含めます。確認や質問は不要です。具体的な計画まで自主的に出力してください。" --model opus --effort high --tools "Read,Grep,Glob" > <出力先>/plan.md
```

### パターン1: 既存挙動の変更

```bash
claude -p "リストエンドポイントは、オフセットではなくカーソルベースのページネーションをサポートする必要があります。これを実現する詳細な実装計画をMarkdownで出力してください。変更を提案する前にソースファイルを読み取り、実際のコードベースに基づいて計画を立ててください。確認や質問は不要です。具体的なコード例まで自主的に出力してください。" --model opus --effort high --tools "Read,Grep,Glob" > <出力先>/plan.md
```

### パターン2: 参照実装を共有する場合

優れた実装が見つかったオープンソースリポジトリのコードを参照として共有する：

```bash
claude -p "並べ替え可能なIDを追加したいと考えています。以下のコードは、これを適切に実行するプロジェクトからのID生成コードです：

[参照コードをここに貼り付け]

同様のアプローチを採用する実装計画をMarkdownで出力してください。実際のコードベースを読み取り、具体的な実装計画を提案してください。確認や質問は不要です。コードスニペットを含む詳細な計画まで自主的に出力してください。" --model opus --effort high --tools "Read,Grep,Glob" > <出力先>/plan.md
```

### パターン3: 調査フェーズ結果を参照する場合

`claude-research` を実行済みで、既存の `research.md` がある場合：

```bash
claude -p "システムを拡張して新しい機能を構築したいと考えています。<出力先>/research.md を読み、その内容を参照して計画を立ててください。これを実装する方法を概説した詳細な実装計画をMarkdownで出力してください。コードスニペットを含めます。確認や質問は不要です。具体的な計画まで自主的に出力してください。" --model opus --effort high --tools "Read,Grep,Glob" > <出力先>/plan.md
```

## 重要な原則

### 1. コードベースの事前読み込み

- **必ず**変更を提案する前にソースファイルを読み取る
- 実際のコードベースに基づいて計画を立てる
- 既存のアーキテクチャやパターンに従う

### 2. マークダウンファイルの使用

- Claude Code の組み込みプランモードは使用しない
- マークダウンファイル（`plan.md`）を使用することで、完全な制御が可能
- エディターで編集したり、インラインノートを追加したりできる
- プロジェクト内で実際の成果物として保持される

### 3. 参照実装の活用

- オープンソースリポジトリで優れた実装が見つかった場合、そのコードを参照として共有する
- ゼロから設計するのではなく、具体的なリファレンス実装を使用して作業する

### 4. 調査フェーズ結果の参照

- `claude-research` を実行した場合、タスク番号やタスク名のディレクトリ配下に `research.md` が生成される
- **必ず**計画作成前に既存の `research.md` を確認し、**そのパスを依頼文に明記して**参照させる
- 調査結果に基づいて計画を立てることで、より正確で実用的な計画を生成できる

## 実行手順

1. ユーザーから依頼内容を受け取る（新機能の説明、変更要件など）
2. 対象プロジェクトのディレクトリを特定し、そこで実行する
3. **既存の `research.md` を確認する**（`claude-research` を実行済みの場合、そのパスを依頼文に含める）
4. 必要に応じて参照実装のコードを依頼内容に含める
5. タスク番号 or タスク名のディレクトリ（例: `.local/issues/<番号>/`）を出力先とし、リダイレクト先に `plan.md` を指定して上記コマンドを実行する
6. 生成された `plan.md` を確認し、要点をユーザーに報告する

## 注意事項

- SessionStart フックの指示が出力に混ざる場合は `--setting-sources user,project` を追加してローカル設定を読ませない

## 出力例の構造

生成される `plan.md` は以下のような構造を持つ：

```markdown
# 実装計画: [機能名]

## 概要
[機能の説明とビジネス成果]

## アプローチ
[実装方法の詳細な説明]

## 変更されるファイル
- `path/to/file1.ts`
- `path/to/file2.ts`

## 実装詳細

### 1. [変更1のタイトル]
[説明 + コードスニペット]

### 2. [変更2のタイトル]
[説明 + コードスニペット]

## 考慮事項とトレードオフ
- [考慮事項1]
- [考慮事項2]

## 実装順序
1. [ステップ1]
2. [ステップ2]
```
